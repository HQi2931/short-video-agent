# 独立效果评测模块

## 核对后的当前能力

- `src/agent.py`：原生逐步循环，模型决定动作；runtime验证参数、执行工具、限制完成。
- `src/llm_adapter.py`：真实HTTP模型适配器，保存请求、公开动作、响应、usage；Mock是明确的预设序列，不是动态模型。
- `src/tools.py`：目录关键词检索、确定性中英文/数字/字幕估时、保守原文证据及品牌规则检查；工具异常撤销旧检查。
- `src/state.py`：脚本、输入、目录、检索素材、规则参与版本检查；完成后编辑会撤销完成状态，导出时再次检查。
- `src/tracing.py`：JSON快照与追加JSONL，禁止重复run_id；next_action是下一动作实际执行后回填。
- 核心测试覆盖正常、修订、工具异常、无素材、无据声明、参数/协议、状态失效及Trace复算；本轮改动前实际重新执行129项通过，见 `evidence/baseline-tests.txt`。
- 已阅读 `README.md`、`docs/03-evaluation.md`、`docs/07-acceptance-audit.md` 及live Trace。历史基线不是本轮结果。03中“43份”是之前阶段；07已更新为46份，包含后续三次人工发起记录。未修改历史文档或证据。

## 本轮补充的维度

独立素材目录上的迁移、20例固定输入与验收契约、动态修订触发率、恢复行为、未触发和未执行分母、工具重复、失败分类、引用追溯、全稿保守无据文本代理、步骤/调用/延迟/usage，以及明确空置的人工语义审核。没有把创作质量当作已验证能力。

## 运行

在项目根目录：

```powershell
.\.venv\Scripts\python.exe -m eval.run
.\.venv\Scripts\python.exe -m eval.run --live --max-steps 12 --max-tool-calls 9 --max-requests 240 --timeout 45
.\.venv\Scripts\python.exe -m pytest tests -q
```

默认只校验数据集，不调用模型。`--live`沿用`.env`，没有完整配置则全部标为未执行；没有Mock回退。每次新建`runs/<UTC时间_UUID>/`，保存数据集快照、配置及代码指纹、逐例JSON/JSONL、输出、评分、报告。失败/取消前的JSONL与partial结果仍保留。请求预算为整批硬上限（传输错误也消耗）；步骤及工具预算为每例上限。到达工具预算后下一决策前终止，不为完成动作额外放宽。现有适配器不提供每响应token上限或账单报价，因此请求上限不是货币成本保证。

案例分布：正常4、超时修正4、无素材3、工具故障3、无据声明3、品牌冲突3。数据集在首轮live之前固定，使用新合成目录，不复用开发示例。超时案例要求先提交双镜审片稿再估时；这是输入要求，不是预设模型动作。未按要求触发超时如实失败。仅一轮随机采样，无seed支持，不能声称统计稳定。

`report.md`列出指标口径；`results.json`保留逐例重放结果、独立终稿工具重算、失败分类和human_review字段。人工必须逐例核对原主题、工具必要性、每条事实蕴含、拒绝解释及创作质量，署名记录时间；默认全部`NOT VERIFIED`。精确自然语言逐声明幻觉率无法由字符串工具可靠计算，因此自动结果显式命名为proxy。不要用历史live重放冒充本轮模型调用。

评分代码更新后，可运行 `python -m eval.rescore eval/runs/<运行目录>`。仅重算已保存证据，新增独立`rescore_<时间_UUID>`目录及评分代码指纹，零模型调用，不覆盖最初评分。`eval/audit.py`可核对包含模型错误后恢复的完整状态链；历史审计工具不支持这种错误动作，仍保持原样。

后续修改Agent提示词或工具应使用新的开发集；本数据集一旦用于调优就不再是无污染保留集。请求失败、预算停止、无稿和零分母均保留，报告不以模型自报成功评分。
