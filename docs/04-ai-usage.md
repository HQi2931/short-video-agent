# AI 辅助开发记录

## 可确认的使用范围

本地 Codex AI 助手根据用户提供的工作要求，从空目录开始创建项目。AI 起草需求矩阵、设计方案、Python 代码、合成素材、品牌配置、测试、Mock 动作夹具、README 与交付文档，并通过本地工具实际运行安装、测试和多场景 CLI 验证。没有使用多 Agent。

AI 生成的主要文件包括 `src/`、`tests/`、`scripts/`、`data/`、`examples/inputs/` 和文档。`examples/outputs/`、`examples/traces/`、manifest、测试输出、环境记录、审计报告均由运行程序生成，未将手写示例伪装成执行结果。

本次参考了 OpenAI 官方结构化输出说明，以核对 JSON 模式不能替代本地 schema 验证；见方案文档的直接链接。没有借用当前聊天模型充当远程 API 调用证据。

## 实际审核与修改的归属

以下均是 **AI 代码检查与修改**，不是候选人人工审核：

- 创建完成状态门禁，绑定当前脚本、输入、素材和规则的指纹。
- 检查出“原有检查通过后又发生业务工具错误”仍可能复用旧结果的边界，统一改为清空两项当前检查。
- 增加素材目录变更后的检索快照一致性检查，阻止旧素材继续验证。
- 增加原主题与素材目录关键词的保守关联检查，防止改写查询后切换为无关产品。
- 将“结果状态符合预期”和“确实发生预期修订行为”分开核验，避免将首稿合格误写成修订闭环已验证。
- live 阶段新增原始模型响应/实际动作和下一轮观察反馈核验，以及从 dotenv 配置值进行精确密钥扫描；新增4项合成日志核验测试。这些测试不被计入真实模型响应数量。

这些修改来自代码审阅，不伪称首轮 pytest 曾经失败。首轮实际测试为108项通过，报告重跑前保存在 `examples/test-history/`；后续新增边界测试和最终数量见当前真实报告。

## 已执行验证与未执行验证

- 实际创建独立 `.venv`，安装 `requirements.txt` 中依赖，执行 pytest 与 CLI 场景，保存真实结果。
- 接口协议的网络对象被 MockTransport 替换；测试中出现 LiveAdapter 类名或 mode=live 不代表真实远程请求。此类日志仅在 pytest 临时目录，不纳入示例 live 证据。
- 用户最初选择离线交付，后续填写本地 `.env` 并要求 live 验证。AI 使用真实 CLI 完成10次远程运行，配置及返回模型为 `deepseek-flash`，保存61条实际模型响应，覆盖8类场景并核验到7条不同有效动作路径。全部请求/响应、工具观察与最终结果由运行代码自动记录，详见 `examples/live-summary.json`。
- 初始12秒超时用例首稿合格，没有触发修订；原批次 `all_expected_behaviors=false` 和退出码1被保留。新增4秒输入后，真实模型基于工具观察将7.64秒改为2.35秒。未伪造原批次通过，也未用固定 Runtime 分支生成修订稿。
- 后续用户提供 `HQi2931/short-video-agent` 并明确授权提交。AI 检查发现其原为空的公开仓库，按既定保密要求将其设为 Private、核实可见性并连接本地 origin。提交与推送使用现有 Git 作者配置；实际提交以 GitHub 历史为准。没有远程 CI 成功或评审授权成功记录。
