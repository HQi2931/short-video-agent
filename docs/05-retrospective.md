# 复盘

最难的问题是让“成功”具有可信证据：模型可能提出finish，但脚本改过、工具失败或引用变化后旧检查不能继续使用。通过绑定脚本/输入/素材/规则指纹、统一检查失效、完成与导出二次门禁，使未验证脚本不能被标成成功。

另一个问题是区分状态与行为：首稿恰好不超时不能证明模型能根据超时反馈改稿；Mock预设修订也不能证明模型自主决策。因而需要保留实际失败观察、下一轮请求和实质变化后的稿件，并离线重算检查。

工程学习包括严格JSON与参数校验、真实API与Mock隔离、有界循环、错误反馈、不可复用的检查状态及可重放Trace。Python原生循环足以解释职责，无需为框架名引入额外复杂度。

多轮开发产生了多个候选快照、批次和相互过时的交付报告，增加审核成本。本轮按本人要求只保留一个实现、一个版本摘要和一组覆盖必需场景的真实记录；五份文档统一描述当前状态。删除重复数据前在仓库外逐字节备份，清理不重写Git历史。

已知未完成：完整语义/创作质量和真人时长验证、跨模型与长期稳定性；题号4已确认，本轮已获本人授权执行GitHub发布。若未来继续开发，应以明确失败或新需求驱动修改，更新当前版本摘要与验证结果；不将已见集合称新盲测，也不把本地版本ID当作最终commit SHA。
