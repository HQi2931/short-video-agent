# 第4题：需求与验收标准

用户是短视频创作者；目标是依据素材生成可编辑、有来源且不超过时长上限的脚本。输入主题、受众、平台、时长、风格，以及产品素材和品牌规则。

必须提供素材检索、时长估算、品牌规则检查三个工具；输出标题、分镜、画面、旁白或字幕、预计总时长、素材来源ID、风险及任务状态。

真实模式必须实现模型选择动作→执行工具→观察结果→再次决策或结束。检索不足时改写查询或询问；工具失败时基于错误恢复或失败；超时或规则失败时修改后重新检查。达到执行上限明确未完成。未通过当前版本检查不得成功，不得编造产品效果。

验收覆盖正常、缺信息、无素材、工具失败、超时修正五场景，并补充规则失败修正。对应真实记录见examples/acceptance-current/manifest.json；离线Mock和单元测试独立于真实模型效果。

范围为CLI、本地确定性工具、真实兼容API和离线Mock、测试与文档。不要求UI、部署、多Agent或生产级Runtime。材料为合成资料；事实字符串核验和估时都有明确限制。

本轮交付为一个本地版本，必需工程目录和五份文档齐全；本人已明确授权本轮commit与push。题号为4，最终Git SHA必须取自实际提交并与远程核对，不以旧远程版本作为本次交付证明。

需求来源：本人于2026-10-30明确题号为4，并转录提供正式页面的题目正文、通用考核规则及GitHub交付规范。本轮以该正式转录逐条核对；不声称助手直接访问了验证后网页，个人考试链接与验证码不进入仓库。
